# ML from Scratch

Personal learning repo for implementing deep learning models and the production LLM
stack from scratch.

## Goal

**Land an AI engineer job at OpenAI-like companies** (frontier AI labs).

Everything here is in service of that: deeply understand how models work by
building them from scratch, the kind of fundamentals these interviews and roles expect.
Then use that understanding to build production agents and RAG with real evals,
fine-tune open models on domain data, and ship monitored end-to-end systems.
No wrapper frameworks that hide the stack: every piece is written here, line by line.

## Planned implementations

Work through these in order.

### Part 1: Foundations

Everything builds on the MLP. CNN and RNN are two separate branches (weight sharing
across space vs. across time), so you can study them in either order. From RNN onwards,
each module builds directly on the previous one.

- [x] Multi-Layer Perceptron (MLP): [`mlp/`](mlp/)
- [ ] Convolutional Neural Network (CNN): [`cnn/`](cnn/)
- [ ] Recurrent Neural Network (RNN): [`rnn/`](rnn/)
- [ ] LSTM / GRU: [`lstm/`](lstm/)
- [ ] Seq2seq + Attention: [`attention/`](attention/)
- [ ] Transformer (GPT-style): [`transformer/`](transformer/)

### Part 2: The modern LLM stack

From the mini-GPT to how frontier models are trained, adapted, evaluated and served.

- [ ] Tokenization (byte-level BPE): [`tokenizer/`](tokenizer/)
- [ ] Modern decoder (LLaMA-style: RMSNorm, RoPE, SwiGLU, GQA, MoE): [`llama/`](llama/)
- [ ] Scaling training (mixed precision, memory, DDP, ZeRO/FSDP, tensor/pipeline parallel): [`distributed/`](distributed/)
- [ ] Fine-tuning (SFT, LoRA, DPO, on domain data and open models): [`finetuning/`](finetuning/)
- [ ] Evals (harness, error bars, pass@k, LLM-as-judge, contamination, CI gates): [`evals/`](evals/)
- [ ] Retrieval-augmented generation (chunking, BM25, dense embeddings, vector index, retrieval evals): [`rag/`](rag/)
- [ ] Agents (tool calling, the agent loop, guardrails, prompt injection, agent evals): [`agents/`](agents/)
- [ ] Serving and monitoring (batching, paged KV cache, quantization, speculative decoding, server, production logs): [`serving/`](serving/)

```
MLP ──┬──> CNN
      └──> RNN ──> LSTM / GRU ──> Seq2seq + Attention ──> Transformer
                                                              │
      ┌───────────────────────────────────────────────────────┘
      └──> Tokenizer ──> LLaMA ──> Distributed ──> Fine-tuning ──> Evals ──> RAG ──> Agents ──> Serving
```

### Part 3: Shipping

- [`projects/`](projects/): one serious end-to-end project every 6–8 weeks (eval set
  first, baseline, served endpoint, monitoring, failure log, write-up), with a template
  and a roadmap that combines the modules above.
- [`papers/`](papers/): the core papers mapped to the exact part to implement and the
  folder that implements it, plus a daily implementation log.

## Structure

Each module lives in its own folder with:

- `README.md`: the theory, with **pictures** (in `images/`, generated by `make_figures.py`), interview questions and exercises
- a **step-by-step terminal visual** (`*_visual.py`) that shows the computation as it happens
- a from-scratch **NumPy** implementation with a **check**: a gradient check
  (`gradient_check.py`), or, for modules without hand-written gradients, a check
  against a brute-force or equivalent computation (`*_check.py`)
- the same thing in **PyTorch**

`python run_checks.py` runs every module's check in order (CI runs it on every push,
see `.github/workflows/checks.yml`). A few scripts have optional extras (loading an open
model with `transformers`, or calling an OpenAI-compatible endpoint); they skip with a
message when the extra is not available, and every module works without them.

## Setup

Run these commands from the repository root. Python 3.9 and 3.11 are tested (CI runs both).

### Windows (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Use the environment's Python directly; activation is not required:

```powershell
.\.venv\Scripts\python.exe run_checks.py
.\.venv\Scripts\python.exe mlp\gradient_check.py
.\.venv\Scripts\python.exe mlp\mlp_numpy.py
```

To open Jupyter:

```powershell
.\.venv\Scripts\python.exe -m jupyter notebook
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run_checks.py              # every module's check, in learning order
python run_checks.py rag agents   # just some modules
python mlp/gradient_check.py      # or one at a time
```

Each folder's `README.md` has a "Suggested order" for its scripts.
